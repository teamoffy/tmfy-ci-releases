# OCI image mirrors — one line per tracked image:
#   <name> <registry/repo> <source> <sed> <k8s> <scope>
#
# <name>            product suffix; releases are tagged oci-<name>/v<version>
# <registry/repo>   image repository to pull (public, anonymous)
# <source>          where the version comes from:
#                     <owner/repo>      the repo's newest release tag
#                     registry:<regex>  the newest tag on <registry/repo>
#                                       matching <regex> (version-sorted,
#                                       whitespace-free)
#                     chart:<component> the image tag <component>'s release
#                                       chart pins (currently chart:cilium
#                                       reads cilium-envoy's tag out of
#                                       cilium's values.yaml)
#                     pin:<tag>         literal tag, for images with no
#                                       derivable source — bump the pin in
#                                       this file to update
# <sed>             expression applied to a release tag to get the image tag,
#                   "-" for none (e.g. k3s releases are v1.x.y+k3sN but the
#                   docker tag is v1.x.y-k3sN). Unused for the other sources.
# <k8s>             how the component tracks a cloud's Kubernetes minor:
#                     any           independent — resolve to the newest version
#                     cilium        newest cilium release whose documented
#                                   e2e-tested Kubernetes set includes the
#                                   minor; cilium runs on every node, so it
#                                   gates the cloud
#                     same:<name>   the version another component resolved to
#                                   (must be listed above)
#                     chart:<name>  the image tag another component's release
#                                   chart pins, at that component's resolved
#                                   version (chart:cilium = cilium-envoy's tag
#                                   from cilium's values.yaml)
#                     minor         must match the k8s minor (v<minor>.<patch>)
#                     minor-short   must match without the leading "1."
#                                   (k8s 1.36 -> v36.<patch>)
#                     minor-trail1  may trail the k8s minor by one
#                   Coupled components gate the per-cloud resolution in
#                   scripts/stacks.txt: if none of their versions supports the
#                   cloud's target minor, the whole cloud resolves one minor
#                   lower.
# <scope>           which clouds run the image: "shared" for every cloud, or
#                   the cloud name for cloud-specific components (that cloud's
#                   CCM/CSI). Only in-scope components gate a cloud's minor.
#
# The resolved tag is the newest release whose image is actually pushed to
# the registry — registry tag listings are unordered and paginated (ghcr caps
# /tags/list at 100 per page), so they cannot resolve latest, and a GitHub
# release can precede (or skip) registry promotion. If nothing recent is
# servable, the product is skipped and picked up by the next run. A pin: row
# whose tag is missing fails the check.
#
# This list covers DaemonSets, CSI sidecars, cloud controllers, and upgrade
# images. The images listed by k3s itself are handled by k3s-system.
